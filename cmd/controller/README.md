# Pi controller

The Go controller polls a primary and optional standby agent/app every five seconds. It saves metrics and traffic under stable `primary`/`standby` identities, independently checks application health, and records events in SQLite. Configure `AGENT_URL`, `APP_URL`, `STANDBY_AGENT_URL`, and `STANDBY_APP_URL`. History endpoints accept `server=primary|standby` and default to primary.

The activation manager implements a 60% CPU warning, 70%/15-second CPU hold, three-probe app-failure failover, optional explicitly validated AI activation, native magic packets, standby health and HAProxy readiness gates, persistent transitions, duplicate suppression, timeout, authenticated retry, and guarded drain/reset. It reconciles proxy state after restart without resending a pending wake. `SCALING_ENABLED` defaults to false. Hardware settings and a private `CONTROL_TOKEN` are required to enable it. The YAML example is not read by the runtime.

Read `/api/status`, `/api/servers`, `/api/scaling`, `/api/prediction`, `/api/metrics`, `/api/metrics/latest`, `/api/traffic`, and `/api/events`. `POST /api/standby/activate`, `/retry`, and `/reset` require the bearer control token. Python predictions are cached and refreshed every 15 seconds; stale or unvalidated predictions cannot activate hardware. Use `./start-pi.sh` for the Pi deployment and follow the [setup guide](../../docs/windows-pi-setup.md).
